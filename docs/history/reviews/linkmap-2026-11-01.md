## Findings

1. **P1: The selected Kartenatelier implementation has not reached main.** PR #1 merged the earlier app at
   `eba0bd848936adf7e555c533328394da1205356e`. The later Kartenatelier commit is on
   `ccr-0d42abb1-kfknng`, after that merge, with no open PR found. Its 90-file difference includes the v2 codec,

   (`linkmap-kit/src/App.tsx:9`) and only dispatches v1 (`src/state/link.ts:26–31`). A v2/visitor URL opened against
   main becomes an empty map rather than the intended document. Open a new PR for the existing branch and validate
   it as the release candidate; editing the description of the merged PR does not include later commits.

2. **P1: Repository-wide CI is red despite the Linkmap job passing.** The existing Actions run
   [41278270850](https://github.com/Schorsches/tinylittleoffice/actions/runs/41278270850) failed two unit tests:
   `test/deploy.test.ts:79` enumerates four workflow files and does not include `linkmap.yml`; the stale-word scan
   at `test/lints.test.ts:295,344` also scans the standalone Linkmap implementation with a rule written for the
   suite's different password design. Nine matches were reported in Linkmap source/docs. Scope that rule to its
   intended product, preserving Linkmap's frozen crypto, and update the workflow inventory test. Subsequent root
   browser/build/reproducibility checks were skipped in that run. The separate Linkmap run passed, so its green
   result is not evidence that the complete repository is green.

3. **P1: Root development-tool advisories remain open.** The full root npm audit reports one high and six moderate
   dependency advisories, including the Cloudflare tooling's transitive HTTP client and Vitest browser tooling.
   Linkmap's full audit reports 11 moderate development-tool advisories and no high or critical advisories; all affected entries in both projects are development dependencies. Linkmap's production packages are unaffected by these reported advisories. This is a root tooling finding, not a claim of an
   exposed production map vulnerability. The fixed HTTP-client patch `undici@7.30.1` and `vitest@5.0.5` are already
   old enough, but the Cloudflare dependency pins need explicit remediation and validation. The suggested Wrangler
   fix `4.156.0` was published on 2026-10-29, so it cannot be used yet under the new rule. Do not silently exempt it
   or treat package age as an advisory fix. Security remediation is separate from this policy-only change.

4. **P1 under the new policy: Existing lockfiles include releases younger than seven days.** The registry audit
   checked 466 distinct name/version pairs across both lockfiles and found 46 ineligible versions, including
   transitive and platform-specific entries. Direct Linkmap changes required eligible predecessors for terra-draw,
   ESLint, fake-indexeddb and typescript-eslint. An exact version pin alone cannot enforce release age. The accompanying
   policy change adds pre-install checks, npm configuration, Dependabot cooldowns and agent instructions, and refreshes
   the affected dependency resolutions using the seven-day cutoff. Advisory checks and application verification must
   also pass for those eligible versions.

5. **P2: Kartenatelier lacks a GitHub validation run for its actual head.** The available successful Linkmap run
   [41278270878](https://github.com/Schorsches/tinylittleoffice/actions/runs/41278270878) tested `eba0bd8`, not `46575c4`.
   Local evidence and the PR description describe later tests, but a new PR should run the combined repository checks
   against the exact commit proposed for merge.

## Boundaries and recommendation

Linkmap is a standalone project within this repository. The suite's root site build is a separate product/build;
merging Linkmap code does not itself deploy the standalone application. The prior local code must not be pushed over
main or the updated branch: GitHub already contains further commits, including the offline cache matching fix.

The new seven-day policy covers direct and transitive npm versions in both existing lockfiles and all existing
workflow installs. The branch listing reports main unprotected; mandatory merge enforcement would additionally need
repository branch rules. This review does not merge, deploy, change those rules, or post a GitHub review on the user's
behalf. The dependency policy is prepared separately from the existing Kartenatelier integration work.
